# Blender、飞船与宇航员资产规范

## 1. 资产目标

制作一艘可以同时支持外部飞行、驾驶舱观察、舱内移动和气闸出舱的模块化探索飞船，以及一套可稳定驱动的宇航员角色与动作。

首轮先做灰盒验证，不直接制作最终高模。只有尺寸、镜头、碰撞、动线和性能通过后，才进入正式美术。

## 2. Blender 工程结构

```text
assets-source/blender/
├─ spacecraft/
│  ├─ spacecraft_blockout.blend
│  ├─ spacecraft_production.blend
│  └─ spacecraft_export.blend
├─ astronaut/
│  ├─ astronaut_rig.blend
│  ├─ astronaut_animation.blend
│  └─ astronaut_export.blend
├─ shared/
│  ├─ materials.blend
│  └─ scale_reference.blend
└─ scripts/
   ├─ validate_scene.py
   ├─ bake_textures.py
   └─ export_glb.py
```

`.blend` 源文件默认不进入 Web 构建目录。是否纳入 Git 由文件大小和 LFS 策略单独决定。

## 3. 坐标与比例

- Blender 与 Three.js 均按米建模，1 Blender unit = 1 meter。
- 角色建议身高 1.75–1.85 m。
- 飞船初始建议长 12–18 m、宽 6–9 m、高 4–6 m。
- +Y 为模型前向或在导出脚本中统一转换；项目内只允许一种约定。
- 原点、轴向和单位必须由自动检查脚本验证。

## 4. 飞船节点规范

必须独立导出或保留命名节点：

- `Ship_Exterior`
- `Ship_Interior`
- `Door_Inner`
- `Door_Outer`
- `Seat_Pilot`
- `Seat_Copilot`
- `Anchor_CockpitCamera`
- `Anchor_ThirdPersonCamera`
- `Anchor_EVA`
- `Anchor_Tether`
- `Thruster_Main_*`
- `Thruster_RCS_*`
- `Collider_*`

硬表面零件使用独立刚体节点，不通过角色蒙皮实现舱门或机械动画。

## 5. 飞船几何预算

| 资产 | LOD0 | LOD1 | LOD2 |
| --- | ---: | ---: | ---: |
| 飞船外部 | 80k–120k 三角面 | 35k–60k | 8k–20k |
| 内舱总计 | 100k–160k | 40k–80k | 不渲染 |
| 单个舱门/机械组 | ≤ 12k | ≤ 5k | ≤ 1k |

飞船外部和完整内舱不应在普通视角中同时高精度渲染。驾驶舱模式隐藏不可见外壳和生活舱细节；外部模式隐藏内舱。

## 6. 材质与纹理

- 优先金属度/粗糙度 PBR。
- 外部和内舱分别使用纹理图集，减少 draw call。
- 基础色使用 sRGB；法线、粗糙度、金属度、AO 使用线性数据。
- ORM 通道建议：R=AO、G=Roughness、B=Metallic。
- 正式资产默认 2K，英雄驾驶舱局部最多 4K。不制作移动端 1K 变体。
- 导出前转换 KTX2/Basis 或 WebP；透明材质仅用于必要区域。
- 仪表动态内容优先使用小尺寸 CanvasTexture 或图集，不为每块屏幕创建独立高分辨率贴图。

## 7. 宇航员骨架

- 使用稳定、唯一的人形骨架；禁止同一 GLB 内存在重复骨架。
- 建议 45–70 根骨骼，手指可根据镜头需求保留。
- 背包、头盔硬壳和工具应作为骨骼附件或刚体节点，不直接跨多个脊柱骨骼蒙皮。
- 每顶点最多 4 个骨骼影响。
- 权重必须检查肩、肘、腕、手指、胯、膝和背包连接区域。
- T/A Pose 只作为绑定姿势，不作为游戏待机动作。

## 8. 动画清单与标准

| 动作 | 循环 | Root motion | 验收重点 |
| --- | --- | --- | --- |
| SeatedIdle | 是 | 否 | 手臂自然、脚不穿座椅 |
| PilotControls | 是 | 否 | 手与控制台位置稳定 |
| StandUp | 否 | 可选 | 起点终点与座椅对齐 |
| CabinWalk | 是 | 否 | 无抱胸、无滑步、脚底稳定 |
| TurnLeft/Right | 否 | 否 | 小空间转身不穿墙 |
| AirlockBrace | 是 | 否 | 手可抓扶手 |
| EVAExit | 否 | 可选 | 不穿舱门与背包 |
| EVAIdle | 是 | 否 | 轻微漂浮，不夸张摆动 |
| EVAThruster | 是 | 否 | 四肢与推进方向合理 |
| EVAGrab | 否 | 否 | 手部 IK 对齐锚点 |
| EVAEnter | 否 | 可选 | 可与出舱动作衔接 |
| SitDown | 否 | 可选 | 终点与驾驶座对齐 |

走路和 EVA 不得直接使用未经角色预览确认的动画。任何手指变形、抱胸、背包扭动、脚陷地或移动滑行动作均判定失败。

## 9. 动画制作流程

1. 清理模型拓扑、法线、缩放和变换。
2. 建立或重建标准骨架。
3. 完成人体与服装权重。
4. 将背包和头盔改为附件或合理权重区域。
5. 在 Blender 中重定向外部动作。
6. 删除不需要的指骨或面部轨道。
7. 修正手臂、手指、髋部和脚底曲线。
8. 为每个动作设置稳定首尾帧和循环。
9. 在测试舱体中预览座椅、走廊、气闸和舱门碰撞。
10. 获得视觉确认后才导出与合成正式 GLB。

## 10. GLB 导出规范

- 一个资产只包含必要场景、网格、材质、骨架和动画。
- 应用缩放和旋转，导出后根节点缩放为 `(1,1,1)`。
- 动作命名与状态机一致。
- 不导出 Blender 相机、灯光和隐藏参考物。
- 使用 Meshopt 压缩；Draco 仅在解码成本可接受时启用。
- 纹理压缩后校验颜色空间和法线方向。
- 输出资产必须通过 glTF Validator，并在 Three.js 独立查看器验收。

## 11. 交付物

每个正式资产必须同时提供：

- 源 `.blend` 文件或可追溯来源。
- 优化后的 `.glb`。
- 资产清单：三角面、顶点、骨骼、动作、纹理、文件大小。
- 预览截图或转台视频。
- 许可证、作者、来源和修改记录。
- Blender 导出脚本版本。
- 运行时对齐参数：比例、前向轴、脚底高度、相机锚点。

## 12. 资产验收门禁

- 飞船外观和内舱比例通过产品确认。
- 宇航员全部关键动作分别从正面、侧面和背面检查。
- 角色连续走动 60 秒无滑步、陷地和动作丢失。
- 背包保持刚性，不随脊柱左右扭曲。
- 手指在待机、行走、抓取和操控时无明显折叠。
- GLB 大小、纹理、三角面和 draw call 满足技术预算。
- 未确认的动作只能作为候选预览，不能下载合成进正式模型。
