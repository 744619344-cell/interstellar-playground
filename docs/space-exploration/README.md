## 执行原则

- 先完成低模垂直切片，再投入高精度飞船和动作制作。
- 只有一个 WebGL 画布和一套长期存在的太阳系状态。
- 不用真实天文尺度直接渲染；采用可解释的视觉尺度。浮动原点是架构目标，**运行时尚未实现**，见路线图 P1-T04。
- 视觉资源按距离和视角加载，任何时刻只保留当前需要的高精度内容。**星体运行时**当前只有 LOD2/LOD1，没有 LOD0。当前 P3-R01 新版飞船已接入驾驶流程，外部远景使用带滞回的 LOD1，驾驶舱或开门时保留活动整船；隐藏和退出取消并释放资源。内舱 LOD1、外部 LOD2 和纹理分区驻留仍未完成，不能视为完整流送系统。
- 飞船与宇航员资产必须经过 Blender 骨架、权重和动作验收，不能直接把不稳定的自动绑定结果投入运行时。
- 《星际穿越》原声仅可在取得完整授权后随产品发布；开发测试音源不得提交仓库。
- 不迁移旧小游戏成绩，不为微信小程序或移动端建立新兼容层。
- 每个阶段通过自动化、浏览器视觉和性能门禁后才能进入下一阶段。
- Phase 0 起默认采用“Codex 前审 → Grok Build 实现 → Codex 独立验收”；任何时刻只有一位代理写入当前任务。
- P3-T07 已通过验收；后续代码均由 Codex 独立完成，不再交接 Grok。P4-T01 已生成第五版宇航员候选并通过基础技术检查，完整外观与动作验收尚未完成，见 [候选资产登记](16-ASTRONAUT-CANDIDATE.md)。
- 当前 [P3-R01](../tasks/2026-09-23-p3-r01-spacecraft-art-redesign.md) 为 `changes_requested`：用户否决自主建模方式和整舱 v6 视觉。未经明确授权，任何代理不得自主建模，包括程序化几何、接口母版及补洞；一般执行许可与 GPT-6/Astra 选择不构成授权。后续采用整舱视觉设计、模块一致多视图与尺寸/接口说明、混元 3D 生成、实际来源检查和试装，详见任务 AG 节。自建 v6 留作被否决记录，产品仍加载该版，尚未替换；完整 LOD、人体净空与长时性能未验收。
